The server sends exactly one response on the scope. The response
finish follows the response, and no frame follows the finish.

```text
[0]                  deleted
[1]                  not deleted: a running container runs the image
[2]                  not deleted: the server keeps no Store
[3][error JSON …]    not deleted
[4]                  not deleted: a platform named is not held
```

- **The sequence.** Exactly one response precedes the response
  finish, and nothing follows the finish. A response finish that no
  response precedes states that the request was not served, as
  [Endpoints](/endpoints/) provides; whether the image is in the
  client's Store is then not stated, and the client learns it from an
  [images::list](/endpoints/images-list/) scope.
- **Deleted.** A payload whose first byte is `0` states, of a request
  that names one or more platforms and does not name every platform
  the client holds of the image, that the client holds the image for
  none of the platforms named, as
  [images::delete](/endpoints/images-delete/) states. Of every other
  request it states that the
  image is no longer in the client's Store. The server sends it after
  the image is removed from the client's Store. From the moment the server sends it, every `images::list`
  scope the client opens omits the image, and every list scope the
  client holds open that was sent the image as added is sent it as
  removed. The server sends nothing after the byte `0`, and a client
  ignores every byte that follows it.
- **In use.** A payload whose first byte is `1` states that a running
  container of the client runs the image at the time of the request,
  and that it was not deleted. The image and the client's listing are
  as they were before the request. The server sends nothing after the
  byte `1`, and a client ignores every byte that follows it.
- **Unsupported.** A payload that is the byte `2` and nothing else
  states that the server holds out no
  [`images.store`](/capabilities/#imagesstore) capability and keeps
  no Store, as [Capabilities](/capabilities/) provides. It is
  the only response of the scope, sent before anything is looked up;
  bytes after it are not read.
- **Platform not held.** A payload that is the byte `4` and nothing
  else states that the request names a platform the client does not
  hold of the image, and that nothing was deleted. The image and the
  client's listing are as they were before the request. The server
  sends nothing after the byte `4`, and a client ignores every byte
  that follows it.
- **The error.** A payload whose first byte is `3` carries an error
  after that byte, running to the end of the payload. The error is
  exactly one JSON value, in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
  This revision prescribes nothing about its content. The error
  states that the image is in the client's Store after the request,
  as it was before it, and that the reason is not a running container.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0`, `1`, `2`, `3` and `4`, and a payload whose bytes after
  `3` are not one JSON value are malformed.
