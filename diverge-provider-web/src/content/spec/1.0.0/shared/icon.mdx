An image ships at most three icons. Each icon is exactly one file in
the directory `.diverge` at the root of the image's filesystem, beside
the [document](/shared/document/). This section defines the three
icons, the size of each one's file, what makes a file a valid icon,
and the frame a server sends for it.

## The three icons

| Icon | Path | The file is |
|------|------|-------------|
| SVG | `/.diverge/icon.svg` | an SVG image |
| 512 | `/.diverge/icon-512.png` | a PNG image, exactly 512 pixels wide and exactly 512 pixels high |
| 64 | `/.diverge/icon-64.png` | a PNG image, exactly 64 pixels wide and exactly 64 pixels high |

- **The name is fixed.** The file name of each icon is exactly the
  name stated above, compared byte for byte. No other name is an
  icon's. No document names an icon, and a server reads no document to
  find one.
- **Each is optional.** An image ships any of the three, all of them,
  or none. An image ships an icon when the file of that name is in its
  `/.diverge`.
- **No other file.** A server that is asked for an icon reads the one
  file of that icon's name, and no other file of the image.

## The size

- **The limit.** An icon's file is at most `1048576` bytes long, the
  limit that [Document](/shared/document/#the-size) states for the
  document, measured as that section states. The limit bounds each
  file by itself: it is not a limit on the three together.
- **Over the limit.** A server reads no byte of an icon's file that
  is over the limit and sends no part of it. The server sends the
  byte `3`, as [The frame](#the-frame) states.

## A valid SVG icon

A file is a valid SVG icon when every one of the following holds. A
server checks them in the following order.

1. **UTF-8.** The bytes of the file are UTF-8.
2. **Well-formed XML.** The text is exactly one well-formed XML
   document.
3. **No document type declaration.** The document has no document
   type declaration. A file that has one is not valid, whatever the
   declaration states.
4. **The outermost element.** The outermost element of the document
   has the local name `svg` and is in the namespace
   `http://www.w3.org/2000/svg`.
5. **No script.** No element of the document, in whatever namespace,
   has the local name `script`, compared without regard to ASCII
   case.
6. **No event handler.** No attribute of any element has a name whose
   first two characters are `on`, compared without regard to ASCII
   case.

A server checks nothing further: not what the image draws, and not
what it refers to.

## A valid PNG icon

A file is a valid PNG icon of a stated side, `512` or `64`, when every
one of the following holds. A server checks them in the following
order.

1. **A PNG image.** The file begins with the PNG signature, and the
   first chunk after the signature is the image header.
2. **The size.** The width the header states is exactly the side, and
   the height the header states is exactly the side. A server reads
   the header before it decodes any pixel, and decodes no image whose
   header states any other size.
3. **It decodes.** Every chunk of the file up to the end of the data
   of the image's first frame is well-formed, the checksum of each is
   correct, and the image data inflates to exactly the pixels the
   header states.

A server checks nothing further: not what the image shows, not its
colour type, not its bit depth, and not any byte after the data of
its first frame.

## The frame

A server that is asked for one icon sends exactly one frame.

```text
[0][the file's bytes …]   the icon
[1]                       the image ships no such icon
[2][error JSON …]         the file is not a valid icon, or could not be read
[3]                       the file is larger than 1048576 bytes
```

- **The icon.** The byte `0` is followed by the file: every byte of
  it, in order, exactly as the image's filesystem holds it. No length
  precedes the bytes, no encoding is applied to them, and no byte
  follows them. The file is a valid icon of the kind asked, which the
  server has checked. The bytes after the tag number at most
  `1048576`.
- **Missing.** The byte `1` alone states that the image ships no such
  icon. Nothing follows the byte. That is a fact about the image and
  not a failure.
- **The error.** The byte `2` is followed by exactly one JSON value
  in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page. An
  error whose `kind` is `icon` states that the file is not a valid
  icon of the kind asked. Any other error states that the server
  could not read the image.
- **Too large.** The byte `3` alone states that the icon's file is
  over the limit. Nothing follows the byte.

## The order

A server decides the frame by the following steps, in the following
order, and stops at the first that applies.

1. **Not there.** The image's `/.diverge` holds nothing under the
   icon's name, or what it holds under the name is not a regular
   file. The server sends the byte `1`.
2. **Too large.** The file is over the limit. The server sends the
   byte `3`.
3. **Not valid.** The file is not a valid icon of the kind asked, as
   [A valid SVG icon](#a-valid-svg-icon) or
   [A valid PNG icon](#a-valid-png-icon) states. The server sends the
   byte `2`, followed by an error whose `kind` is `icon`, and sends no
   byte of the file.
4. **Otherwise.** The server sends the byte `0`, followed by the
   file's bytes.

A server that cannot obtain or read the image sends the byte `2`,
followed by an error, at whichever step it fails.
