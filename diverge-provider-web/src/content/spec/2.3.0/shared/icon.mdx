An image ships at most three icons. Each icon is exactly one file in
the directory `.diverge` at the root of the image's filesystem, beside
the [document](/shared/document/), and the document's `icons` names
it. This section defines the three icons, the name of an icon's file,
the size of the file, and the frame a server sends for it.

## The three icons

| Member of `icons` | The file is |
|-------------------|-------------|
| `svg` | an SVG image |
| `512` | a PNG image, 512 pixels wide and 512 pixels high |
| `64` | a PNG image, 64 pixels wide and 64 pixels high |

- **Each is optional.** An image ships any of the three, all of them,
  or none. A member that is absent states that the image ships no
  such icon.
- **The author's word.** What a file holds is its author's statement.
  A server does not read an icon's bytes: it does not check that the
  file is an SVG image or a PNG image, and it does not check the
  image's width or height. A server sends a file that is not what its
  member states exactly as it sends one that is.

## The name

The value of each member is the name of the icon's file: the path of
the file is `/.diverge/` followed by the name.

- **The length.** A name is at least `1` byte and at most `255` bytes
  long.
- **The bytes.** Every byte of a name is an ASCII letter, an ASCII
  digit, `.`, `-` or `_`. A name therefore holds no `/` and no `\`.
- **The first byte.** The first byte of a name is not `.`. A name is
  therefore neither `.` nor `..`.
- **Not the document.** A name is not `DIVERGE.md`, compared byte for
  byte.
- **Otherwise.** A document whose `icons` holds a string that is not
  a name is [not a document](/shared/document/#not-a-document).

## The size

- **The limit.** An icon's file is at most `1048576` bytes long, the
  limit that [Document](/shared/document/#the-size) states for the
  document, measured as that section states. The limit bounds each
  file by itself: it is not a limit on the three together.
- **Over the limit.** A server reads no byte of an icon's file that
  is over the limit and sends no part of it. The server sends the
  byte `3`, as [The frame](#the-frame) states.

## The frame

A server that is asked for one icon sends exactly one frame.

```text
[0][the file's bytes …]   the icon
[1]                       the image ships no such icon
[2][error JSON …]         the icon could not be read
[3]                       the file is larger than 1048576 bytes
```

- **The icon.** The byte `0` is followed by the file: every byte of
  it, in order, exactly as the image's filesystem holds it. No length
  precedes the bytes, no encoding is applied to them, and no byte
  follows them. The bytes after the tag number at least `0` and at
  most `1048576`.
- **Missing.** The byte `1` alone states that the image ships no such
  icon. Nothing follows the byte. That is a fact about the image and
  not a failure.
- **The error.** The byte `2` is followed by exactly one JSON value
  in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
- **Too large.** The byte `3` alone states that the icon's file is
  over the limit. Nothing follows the byte.

## The order

A server decides the frame by the following steps, in the following
order, and stops at the first that applies.

1. **No document.** The image ships no document. The server sends
   the byte `1`.
2. **The document cannot be read.** The document is over the limit of
   its size, or is [not a document](/shared/document/#not-a-document).
   The server sends the byte `2`, followed by an error whose `kind`
   is `info`.
3. **Not named.** The document's `icons` is absent, or has no member
   for the icon asked. The server sends the byte `1`.
4. **Not there.** The image's `/.diverge` holds nothing under the
   name, or what it holds under the name is not a regular file. The
   server sends the byte `1`.
5. **Too large.** The file is over the limit. The server sends the
   byte `3`.
6. **Otherwise.** The server sends the byte `0`, followed by the
   file's bytes.

A server that cannot obtain or read the image sends the byte `2`,
followed by an error, at whichever step it fails.
